# Model guidance registry

Keep small, dated provider-specific guidance cards only when they improve a named
workflow in evaluation. This public scaffold ships no adopted model-specific cards.
Verify official documentation before proposing one; provider advice does not grant
permissions or change spending limits.

## Provider-neutral baseline

State the outcome, acceptance checks, constraints, evidence and desired output shape.
Retrieve only relevant context. Match tools and verification to the task, preserve
authorization boundaries, and checkpoint work before exhausting available capacity.

## Evaluation and update boundary

Use the [skill evaluation procedure](../skills/skill-evaluation/SKILL.md) to compare
representative tasks under the same tool, data and capacity boundaries. Record real
quality, latency and usage evidence where available; do not invent missing telemetry.
Include a recovery case and a case requiring rejection of an unauthorized action.

Treat a passing evaluation as evidence for review. It does not automatically install
guidance, change provider defaults, grant tools, or authorize recurring evaluation.
Keep owner-specific results and raw traces in a verified private destination.
