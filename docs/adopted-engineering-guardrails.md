# Engineering guardrails

Use these proportionally for consequential changes:

- clarify ambiguity that would materially change the outcome;
- answer empirical architecture questions with a disposable prototype or benchmark;
- build observable behavior in small testable slices;
- review separately for repository standards/safety and for the original intent/outcome.

Do not add ceremony to trivial work. If these guardrails create more friction than value, narrow them explicitly rather than silently accumulating process.
